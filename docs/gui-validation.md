# 高度GUIによる検証

`studio-demo` は、単純なボタン集では見つからない不足を洗い出すためのネイティブ編集アプリである。
WebView、HTML、CSS、JavaScriptは使わず、winitのOSイベントとwgpuのネイティブGPUバックエンドで動く。

## 一つの画面で通している機能

- 可変幅のレイヤー、ノードキャンバス、インスペクターと可変高タイムライン
- 角丸、境界、影、グリッド、接続線、トグル、スライダー、再生ヘッド
- 各ペインの論理座標クリップ。Windfoil文字にも同じクリップを適用
- 安定した`WidgetId`によるhover、active、focus状態
- ポインターキャプチャによるノード、ペイン境界、スライダーの継続ドラッグ
- レイヤー選択とスクロール、キャンバスのパンとズーム
- Tab / Shift+Tabのフォーカス巡回、Enter実行、ショートカット、検索文字入力
- 再生中だけ約8ms後の再描画を予約し、停止中はイベントが来るまで待機
- サイズ非依存の`TextRun`を`TextCache`に保持し、同じ文字列を再シェーピングしない

## 検証方法

```sh
cargo run --release --features portable --bin studio-demo -- --smoke
```

合成入力でレイヤー選択、ノード移動、Opacityドラッグを実行した後、1280×768のオフスクリーン
テクスチャへ描画する。GPU出力を読み戻し、タイトルの文字ピクセルが存在することを検査し、
`build/studio-smoke.ppm`へ保存する。これは描画経路と状態遷移の回帰検査であり、実入力や表示装置の遅延計測ではない。
同時に2,048回のUI命令構築を測り、CPU側のp50/p95/p99/最大値を表示する。

## この実装で判明した次の不足

現在の機能で複数ペインの編集画面は組める。ただし、一般のアプリへ公開できる完成度には次が必要である。

1. 制約ベースレイアウト。複数行Grid、単一軸Flexと長い一覧の仮想化は実装済み。
2. 行折り返しと視覚座標によるキャレット移動。TextEditの改行、論理行・単語移動、選択、キャレット、
   IME preedit、cut/paste API、undo/redoは実装済み。
3. 解析的文字renderer単体での混在方向の段落分割、改行、禁則。順序付きフォントフォールバックと、
   Studioでのシステムフォント・BiDi・カラー絵文字fallbackは実装済み。
4. OSアクセシビリティツリーへの具体的な接続。role/state/boundsの共通意味情報、フォーカス外観、
   backend非依存の出力契約は実装済み。
5. 複数ウィンドウ。メニュー、ポップアップ、モーダルのstackと入力遮断は実装済み。
6. GPUタイムスタンプ、メモリ、起動時間、待機時CPU、実入力から発光までを含む継続ベンチマーク。

したがって、現段階は「高度なGUIを構築できる描画・入力コア」であり、汎用GUIライブラリの完成版ではない。
